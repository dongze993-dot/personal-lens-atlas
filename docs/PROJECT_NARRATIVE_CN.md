# 项目叙述与技术复盘：Personal Lens Atlas

> 本文面向公开作品集、技术面试和协作者阅读。它说明项目如何定义、如何根据实机反馈调整路线，以及当前已验证和未验证的边界。

## 项目定位

Personal Lens Atlas 是一个面向 Windows 11 普通内置/USB 摄像头与 CPU 的本地实时视觉处理 MVP。目标是在使用者阅读屏幕内容时，让预览画面中的眼睛尽量更接近看向物理摄像头镜头；它不是鼠标眼动追踪，也不是云端生成式服务或 NVIDIA Broadcast 的复刻。

## 从需求定义开始

项目启动时，将“像 NVIDIA Eye Contact 一样自然”的期待拆解成可验证的工程约束：

- 环境固定为 Windows 11、Python 3.11、普通摄像头、CPU、MediaPipe 与 OpenCV，不能改动已有 Python 环境，不依赖 RTX、CUDA 或 NVIDIA Broadcast。
- 先以真实摄像头的 `Original / Corrected` 对比验证视觉效果，只有第一阶段成立，再进入虚拟摄像头与会议/面试软件适配。
- 黑点、双瞳孔、眼皮被覆盖、瞳孔越界，以及滑条有数值但视觉不改善，均视为需要定位的产品缺陷。
- 摄像头视频、参考眼区图片和姿态数据必须只保留在本机；公开代码不能包含使用者生物特征素材。

这种定义将产品目的、设备边界、验收条件、失败模式和隐私要求同时固定，使后续实现能被实机检查，而不是只依赖抽象指标。

## 从失败现象到技术路线调整

早期局部瞳孔/眼区实验在大幅转眼时暴露出固定黑点、双瞳孔、瞳孔与眼皮脱离或被眼皮遮挡等问题。它们说明“调大 correction strength”不能解决根本问题：固定的小范围替换不适合当前的视觉目标。

当前主路线因此改为个人化真实参考图集：

1. 引导使用者在 9 个舒适头部姿态下持续直视物理镜头；
2. 以本地 JSON 记录帧号与姿态，避免依赖普通摄像头视频容器中不可靠的 FPS；
3. 按清晰度、亮度、睁眼程度和虹膜到眼皮距离筛选真实参考眼区；
4. 依据实时 yaw/pitch/roll、眼睛开合度匹配参考，用眼角和眼睑几何仿射对齐；
5. 只在当前与参考眼皮开口的交集内做羽化融合；闭眼、低置信度、姿态无覆盖或颜色异常时回退原始画面。

该路线主动牺牲任意角度的泛化能力，换取在普通 CPU 电脑上更可控的个人化效果和更安全的失败模式。

## 面试或作品集中的讲述方式

> 这个项目的重点不是把瞳孔硬移到中间，而是先定义清楚问题和验收方式。我把目标限定为普通 Windows CPU 电脑上的本地预览，并明确先验证视觉质量、再做虚拟摄像头。实机测试表明小范围瞳孔修补会造成黑点、双瞳孔和眼皮不一致，因此改为录制本人在不同头姿下直视镜头的真实眼区，再根据当前姿态匹配参考，并且只在当前眼皮开口内保守融合。它不宣称无限泛化，而优先保证本地可控、隐私处理和不可靠时回退原图。

## 可以如实体现的能力

- 将抽象的视觉体验目标拆解为硬件边界、隐私边界、视觉验收标准、失败场景和分阶段交付条件。
- 根据真实摄像头反馈否定不成立的局部贴图路线，推动方案收敛为可验证的个人参考库与眼皮安全融合。
- 借助 AI 编程协作推进原型，同时保持依赖兼容性、公开数据审查、可复现脚本与技术边界说明。
